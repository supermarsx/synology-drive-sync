Sync status and resync

This page answers two questions about one profile: what state each file is in, and how to force a file back onto the NAS. It opens with a stored summary, and the per-file comparison runs when you choose Check status.

Sync summary: what the last check recorded

The summary at the top of the page is read back from small totals that each check stores when it finishes. Opening it walks no folder and sends no request to the File Station destination, so it answers immediately even on a low-powered NAS and even while a sync is running.

Because it describes the last check rather than this moment, it says how old it is. The age shown is that of the oldest observation contributing to it, not the newest, so it is a claim true of every profile in the total rather than one that describes the freshest part and implies it of the rest. A profile that has never been checked is named as never observed, and while any profile is in that state the combined figure is incomplete and understates what is pending. If a check ran out of its scan budget, every figure it contributed is a floor rather than a count and is marked with a trailing +. If two profiles cover overlapping folders, no combined figure is shown at all, because summing them would count the shared files twice; the per-profile rows remain exact and the page says why the total is absent. Refresh re-reads the stored totals; it does not re-check anything.

Checking status: never stale, and never free

The per-file check keeps no index. Both the local folder and the File Station destination are walked again every time, and each entry is compared with the same code path a real sync uses, so a status row cannot disagree with what a sync would do. Because that answer is rebuilt on every run, this page deliberately has no refresh timer: the check runs only when you ask it to, and it is what refreshes the summary above for next time. On a low-powered NAS, prefer a folder scope over the whole tree.

States

In sync
Present on both sides and equal under the profile's comparison setting.
Differs
Present on both sides and scheduled for upload. The Why column names the evidence that decided it, such as differing size or differing modification time.
Missing remotely
Present locally with no entry at the destination path.
Remote only
Present on the NAS with no local counterpart. It is removed only by a mirror run with deletion separately approved, never by this page.
Type conflict
Both sides exist but one is a file and the other a directory. This is the state that makes a sync fail rather than proceed.
Excluded
Never synchronized, because an ignore rule, a DSM-managed path, or a mount boundary excludes it.

Needs attention is the default view and covers type conflicts, missing remotely, differs, and remote only.

Totals and pages

The totals above the table always describe the whole scope, not the rows drawn below it, so the counts stay honest while a search narrows the listing. A page never exceeds 200 rows; the package refuses a larger request rather than returning an unbounded listing. Use Next page and Previous page to move through a large scope. If a walk cannot finish, the page says so and the totals are reported as a lower bound.

Searching for a file

Search file name lists only entries whose file name contains the text you type, compared without regard to case. It narrows which rows are listed and never changes the reported totals. Folder or file is a source-relative path rather than a pattern, and naming a single file reports just that file.

Resync

A resync re-uploads without comparing, replacing the remote copy whatever it currently holds, including a copy that is identical or newer. It never deletes: removing remote-only entries remains a separate mirror decision.

It runs in two steps and cannot be collapsed into one. Plan re-upload changes nothing; it lists every file that would be overwritten, totals the bytes, and prints a ticket derived from that exact list. Confirm this exact plan sends the ticket back and performs the upload. Confirming therefore proves the list was seen, not merely that the button was pressed twice.

If the source or destination changed in between, the ticket no longer matches what would be overwritten. The package refuses, changes nothing, and shows a refreshed list with a new ticket in its place, so a changing NAS never becomes a loop. A ticket carries no clock and does not expire on its own; only a change to what would be overwritten invalidates it.

Leave Folder or file empty to re-upload everything in the profile, name a folder to re-upload its subtree, or choose Re-upload on a table row to plan that single file.

When the controls are unavailable

Status checks and resync are operational actions. They are blocked while another operation is running, and while the security policy withholds operational actions. Confirmed re-uploads take the package management lock and are recorded in the package audit trail and activity feed like any other operation that changes the destination.
