Notifications

Package alerts and Session preferences are separate tabs. Package alerts use DSM desktop delivery with fixed localized title and message keys. Session preferences contain the open-AppWindow browser and audible fallback. Dynamic paths, profile names, usernames, URLs, tokens, and error output are deliberately excluded.

DSM desktop alert policy

Enable alerts
Master switch for package-owned DSM desktop notifications.
Notify on success
Sends the fixed completion event after a successful sync.
Notify on failure
Sends the fixed failure event after the failure threshold is met.
Failures before alert
Consecutive failures required before delivery.
Cooldown
Minimum seconds between repeated failure alerts.

Recognized events

  • sync_succeeded - fixed sync completion title and message.
  • sync_failed - fixed sync failure title and message.
  • doctor_failed - fixed Target Doctor failure title and message.

DSM system log

Desktop alerts are not durable: an administrator who was not signed in when one fired never sees it. The package can additionally write a fixed sentence per event to DSM's own system log through /usr/syno/bin/synologset1. This is off by default and has no dashboard field; configure it with configure-alerts over SSH.

--system-log
Enables system log delivery. Requires a message identifier.
--system-log-level
info, warn, or err; the lowest severity delivered. Default warn.
--system-log-message-id
An identifier from DSM's own system-log message catalogue, in 0x hexadecimal form. The catalogue belongs to Synology and cannot be extended by a third-party package, so this package ships no identifier of its own and delivery stays inert until you supply one you have verified on your DSM build.

Delivery reuses the alert failure threshold and is rate-limited by the alert cooldown independently per event group, so a routine failing every five minutes produces one system log entry per cooldown rather than one per failure. Events cover sync results, Target Doctor failures, dashboard authentication and request failures, rejected changes, package service start/stop/restart, and install and upgrade. If the DSM binary is absent or refuses the call, the run keeps its own result and Activity records notification.unavailable.

This package acquires no DSM resource worker, so it registers no Control Panel notification rule and installs no Log Center pattern. Email, SMS, mobile, and CMS delivery cannot be enabled through this package.

Open-session signals

Browser notification and audible-cue settings are optional, non-secret preferences for the current browser. Saving them requires the notification-change policy and records a fixed session-notifications audit event before local persistence. They operate only while the AppWindow session can observe a newly failed result and do not replace DSM package alerts.
