Activity and logs

Activity shows bounded structured events and recent package log output. Browser polling runs only while this page and the DSM document are visible.

Structured activity

Each event can include time, code, profile, state, category, and level. Events describe package decisions such as queue acceptance, controller execution, routine transitions, notifications, and terminal results. Use the category and exact-level selectors to narrow the rendered event list without deleting or changing durable records. An absent field is displayed as unknown rather than inferred.

Log source and line limit

Select all logs or limit the view to audit, controller, scheduler, or sync output. Audit is the administrator-action trail; it is separate from ordinary controller output. The line limit bounds both the request and rendered response. The package also enforces response-size limits before content reaches this AppWindow.

Pause and clear

Pause live updates stops browser refreshes; it does not stop the package service or an active sync. Clear view replaces only the current rendered text. It does not delete durable package logs.

Troubleshooting an unavailable bridge

  1. Confirm that the package is running in Package Center.
  2. Sign in to DSM again and reopen the AppWindow so the same-origin session can be re-evaluated.
  3. Check the package service and controller logs over an administrator-approved DSM support path.
  4. Do not expose package-private log or socket paths through a public web alias.

Privacy

Secret values must never appear in status, activity, or log responses. Remote logging is separately configured per profile and accepts only an HTTPS collector URL; its token remains write-only.
