Activity and logs

Activity shows bounded structured events and recent package log output. Browser polling runs only while this page and the DSM document are visible.

Structured activity

Each event can include time, code, profile, state, category, and level. Events describe package decisions such as queue acceptance, controller execution, routine transitions, notifications, and terminal results. Use the category and exact-level selectors to narrow the rendered event list without deleting or changing durable records. An absent field is displayed as unknown rather than inferred.

Log source and line limit

Select all logs or limit the view to DSM API, Doctor discovery, audit, controller, scheduler, or sync output. Audit is the administrator-action trail; it is separate from ordinary controller output. Doctor discovery contains private, package-local structure evidence captured from Target Doctor: the profile, discovery scope, total and truncation state, plus at most five logical path/name and folder/file entries. Empty discovery remains visible. This source never contains credentials, sessions, target URLs, ACLs, digests, or server detail, and it is not sent to a profile's generic remote log collector. Retained rotations are read from oldest to newest before the active file, then only the newest requested suffix that fits the response budget is returned. The line limit bounds both the request and rendered response. The package also enforces response-size limits before content reaches this AppWindow.

Times on every line

Every rendered log line shows when the package wrote it. The time comes from the record itself, not from when the browser read it: each package log stamps its own records, and the dashboard reads that stamped field back and renders it in this browser's local time zone, in the same format as the structured activity list above. A line that carries no recorded time is shown as Time not recorded rather than being given an invented one or hidden. That is uncommon and means the line is a fragment: a partial record left at a rotation boundary, or a very long record shortened by the package's per-line ceiling before it reached this window.

Pause and clear

Pause live updates stops browser refreshes; it does not stop the package service or an active sync. Clear view replaces only the current rendered text. It does not delete durable package logs.

Clear, in the header of an individual log, is different: it empties that durable log on the NAS. The active file is replaced with an empty package-private file and its retained rotations are removed, which returns their space to the volume. Evidence already collected is lost, so copy anything still needed first. The action asks for confirmation, is unavailable while another package operation is in flight, and requires the security policy to permit operational actions.

The audit log cannot be cleared from this dashboard, and its Clear control stays disabled and says so. It is the record of which administrator cleared which log, so a control that emptied it would remove the evidence of its own use. Every clearing of any other log is itself written to the audit log and appears in the structured activity list.

Troubleshooting an unavailable bridge

  1. Confirm that the package is running in Package Center.
  2. Sign in to DSM again and reopen the AppWindow so the same-origin session can be re-evaluated.
  3. Check the package service and controller logs over an administrator-approved DSM support path.
  4. Do not expose package-private log or socket paths through a public web alias.

Privacy

Secret values must never appear in status, activity, or log responses. Remote logging is separately configured per profile and accepts only an HTTPS collector URL; its token remains write-only.
