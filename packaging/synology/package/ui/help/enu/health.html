Health and Target Doctor

Target Doctor performs bounded preflight diagnostics for all profiles or one selected profile. The AppWindow waits for terminal Doctor evidence rather than treating queue acceptance as success.

Checks

  1. Source integrity: walks the complete source and hashes payload files.
  2. Reverse-proxy routing: requires File Station API discovery instead of accepting an HTML login or portal fallback.
  3. Authentication: validates destination credentials without returning secrets to the AppWindow.
  4. Destination permission: checks the configured path or its nearest existing ancestor.
  5. Capacity and latency: reports only evidence actually returned by the target.

Disposable write test

The optional write test creates a unique probe, verifies it, and removes it. It requires package capability, an explicit checkbox, a second cleanup acknowledgement, and a confirmation dialog. Use only a non-critical destination. A cleanup failure is diagnostic failure evidence and must be investigated.

Terminal and unknown outcomes

Completed and failed are terminal package results. A lost POST acknowledgement is recovered with at most two exact replays of the same body and client request ID, which resolve to the same queued job. If that job still cannot be observed because result evidence is invalid, expired, repeatedly unavailable, or exceeds a bounded operation's overall observation limit, the UI reports outcome unknown with request and job correlation when available. Only the affected scope and operations that depend on it are paused; independent configuration remains usable. Inspect authoritative package state, Activity, and logs before another request in that scope.
