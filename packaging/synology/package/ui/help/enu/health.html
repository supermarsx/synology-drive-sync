Health and Target Doctor

Target Doctor performs bounded diagnostics for all profiles or one selected profile. The AppWindow waits for terminal evidence rather than treating queue acceptance as success, and never marks missing or truncated evidence as healthy.

Diagnostic levels

Quick
Checks URL policy, TLS and reverse-proxy routing, and DSM/File Station discovery without resolving credentials or opening a session.
Standard
Adds the package-visible source scan, authentication, required File Station capabilities, bounded target inventory, and logout. With a configured destination, it checks permission and samples direct children. Without one, it skips permission and samples visible shared-folder roots without selecting or traversing a share. This is the default.
Extensive
Adds complete source MD5, CRC32, and SHA-256 hashing plus the deepest authenticated, read-only target capability checks and the same bounded inventory branch. Extensive does not write unless the separate disposable write test is enabled and confirmed.

Target breakdown

  1. Routing and TLS negotiation
  2. DSM API discovery
  3. DSM session authentication
  4. File Station capabilities
  5. Destination permissions
  6. Destination inventory
  7. Disposable write, verify, and cleanup
  8. Session logout

Every section is reported as OK, warning, not OK, or skipped with bounded detail and timing scope. Routing and discovery can share one connection measurement; the UI labels shared timing instead of counting it twice.

Remote folder and file proof

Standard and Extensive authenticate and request one sorted, non-recursive bounded inventory page. With a configured destination, Doctor checks permission and samples its direct children. Without a destination, Doctor skips permission and samples visible shared-folder roots without selecting or traversing any share. Either branch displays at most five folders or files. Each entry contains only bounded relative path and name, kind, file size and modified time when available, mount-boundary state, and explicit text-truncation flags. The total and truncated marker show when more entries exist. Doctor does not read those payloads or use this sample in place of Plan or Run's complete inventory.

Disposable write test

The optional write test is available only at Extensive depth. It creates a unique probe, verifies size, modified time, MD5, CRC32, and SHA-256, optionally exercises server-side copy, and removes the probe. It requires package capability, an explicit checkbox, a second cleanup acknowledgement, and a confirmation dialog. Use only a prepared non-critical existing destination. A cleanup failure or reported leftover path must be investigated before retrying.

Terminal and unknown outcomes

Completed and failed are terminal package results. A package-level failure cannot be hidden by an independently successful target check. Complete structured output is accepted only inside the one-MiB API contract; malformed output, the package truncation marker, or the legacy 64-KiB boundary becomes a visible not-OK integrity result. Bounded trailing controller warnings remain visible.

A lost POST acknowledgement is recovered with at most two exact replays of the same body and client request ID, which resolve to the same queued job. If that job still cannot be observed because result evidence is invalid, expired, or repeatedly unavailable, the UI reports outcome unknown with request and job correlation when available. Only the affected scope and dependent operations are paused; independent configuration remains usable. Inspect authoritative package state, Activity, and logs before another request in that scope.
