Routines and realtime hooks

The page opens on Configured profiles, where each saved routine can be inspected and selected. Selecting one switches to New routine and loads that profile in the routine editor. Each profile can have one saved routine. A routine remains inert until it is saved and enabled. Choose Sync for a real transfer or Plan only for read-only comparison.

Execution modes

Interval
Runs after the configured number of seconds. It has no weekday or time-window restriction.
Daily window
Runs on the selected weekdays and only between the start and end times in DSM local time.
Realtime
Observes source changes, waits for a full quiet debounce period after the latest event, performs preflight, and starts a run. It has no interval or calendar window. The debounce defaults to 45 seconds. Dependency deferral preserves the pending event; a newer event restarts the quiet period. A consumed native event also refreshes the fallback fingerprint, so polling cannot dispatch it early or a second time. When a native change hook is unavailable, the package reports and uses the configured polling fallback.

Retries

Whole-action retries default to five. The base delay is 10 to 300 seconds. Exponential backoff can be enabled to double later delays or disabled to keep the base delay fixed; every delay is capped at five minutes. A pending retry owns admission until its deadline, so daily cadence and realtime events cannot bypass the delay. Retries do not permit overlapping operations.

Dependencies and weekdays

Wait-for dependencies require selected profile routines to finish first. Avoid dependency cycles. Daily mode requires at least one active weekday and evaluates its window using the NAS clock, so keep DSM time synchronization healthy. Interval and realtime modes ignore calendar controls.

Deletion policy

A routine cannot independently enable deletion. It can only permit deletion already allowed by the profile, and its deletion approval ceiling adds another limit. The ceiling is a non-negative integer no greater than 2147483647 on every supported NAS architecture. Use a plan to review proposed removals before enabling either layer.

One host-local lock

Manual plans, manual syncs, Doctor operations, and scheduled routines coordinate through package state. A long-running sync cannot pile up concurrent sync processes; subsequent routine work waits or records the controller decision.

Removing a routine

Removing a routine stops package automation for the profile. The profile, credentials, and synchronized files remain intact.
