Profiles and credentials

A profile binds one local source to one File Station origin, DSM account, and logical destination path. Names use letters, digits, underscores, or hyphens and cannot be renamed after creation.

Required fields

Local source
A canonical readable folder below an internal, USB, or SATA DSM storage root, such as /volume1/Source. Use Browse NAS or enter it manually.
File Station URL
The HTTPS origin of the destination NAS. Plain HTTP requires the explicit controlled-LAN override.
DSM username
The least-privileged destination account required to reach the configured path.
Remote logical path
A File Station path such as /home/Drive/NAS Backup, not a local filesystem mount.
Comparison
Content requires size, MD5, IEEE CRC32, SHA-256, and modification time. It also requires File Station download permission and streams selected remote bytes for verification. Metadata compares size and time; size-only is the weakest evidence.
Concurrent uploads
One through sixteen workers. Start low on memory-constrained NAS models.

Choose real folders

Browse NAS shows only canonical non-symlink DSM volume folders the package identity can read and traverse. DSM-managed, package-private, unreadable, and arbitrary filesystem roots are not exposed. The exact selected or manually entered path is checked again immediately before save.

Browse target unlocks only after Test authentication succeeds for the unchanged connection and credential draft. The package discovers the documented File Station APIs, lists actual accessible shares and child directories, and closes the temporary File Station session. The short-lived proof expires after at most five minutes or immediately when the draft changes. Testing a stored credential is an operational action; replacing or clearing credentials remains governed separately by the secret-change policy.

Deletion and empty-source guards

Remote deletion requires approval in the saved profile and again for the operation or routine. The maximum-deletion value is a hard ceiling. An unexpectedly empty source fails closed unless Allow an empty source is enabled both by the global Security ceiling and by this profile. Review a plan after every exclusion or source-path change.

Network and retry controls

Retries cover transient failures. Upload and connection timeouts are bounded. Maximum rate uses bytes per second; zero means unlimited. A CA certificate path should reference a package-readable PEM bundle. Accepting invalid certificates disables identity verification and requires a separate interception-risk acknowledgement.

Exclusions and logging

Enter one exclusion pattern per line. Log format can be human or json; progress can be auto, always, or never; and command output can be human, json, or ndjson. Quiet suppresses terminal-style output independently, so nonzero verbosity can still raise durable log detail. Remote logging requires HTTPS; required mode can fail the operation when delivery fails, while best effort records the delivery problem without failing the sync.

Protected credentials

Password, TOTP seed, and remote-log token have three independent operations: keep, replace, or clear. Replacement fields are write-only. Saving first validates the exact source, then applies profile configuration and requested secret operations in order. A bounded save shows live progress; if a later stage fails or its accepted outcome becomes unknown, the editor stays recoverable, clears only confirmed stages, and retains unapplied draft values for Activity and Logs inspection. Every mutation and autosave is then locked in the current AppWindow. Preserve the draft, reconcile authoritative profile and credential-presence state, and reopen the AppWindow before making another change; do not resubmit from the uncertain session.

Remove a profile

Deleting a profile removes package-owned configuration and protected credentials. It does not delete local source files or already synchronized destination files.
